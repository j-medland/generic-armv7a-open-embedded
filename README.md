# generic-armv7a (vfp, soft-float) — kas / kas-container project

Use `kas` to build a rootfs, ipk package feed and linux SDK for a generic ARMv7-A target with a VFP unit using the OpenEmbedded **warrior** release built directly from `bitbake` + `openembedded-core` + `meta-openembedded`.

This _should_ provide the tools and package feeds to compile for LabVIEW Hobbyist Toolkit Beaglebone-Black and RaspberryPi targets.

Most of the content of this repository was created with Claude.ai (note the em-dash in the title 🙄) and in-so-far as any copyright/ownership applies, it is released under the BSD-0 licence.

## Usage

### 1. Build the Ubuntu 16.04 container image

```bash
docker build -t kas-ubuntu1604:latest -f docker/Dockerfile.ubuntu-16.04 docker
```

### 2. Build

From the directory containing `kas-project.yml`:

```bash
KAS_CONTAINER_IMAGE=kas-ubuntu1604:latest kas-container build kas-project.yml
```

Or, to poke around first:

```bash
KAS_CONTAINER_IMAGE=kas-ubuntu1604:latest kas-container shell kas-project.yml
```

Outputs land under `build/tmp/deploy/`:

* `images/generic-armv7a/core-image-minimal-generic-armv7a.tar.bz2` — rootfs (only, per `IMAGE_FSTYPES`)
* `ipk/`                                                            — the package feed
  (`Packages`, `Packages.gz` generated by the `package-index` target
  in `target:`)
* `sdk/poky-glibc-x86_64-core-image-minimal-armv7a-toolchain-*.sh`  — standard
  SDK installer (cross toolchain + sysroot matching `core-image-minimal`),
  built by the `core-image-minimal:do_populate_sdk` target in `target:`

## Notes

* `PACKAGE_FEED_URIS` in `kas-project.yml` is a placeholder
  (`http://feeds.example.local/generic-armv7a`) — point it at wherever
  you'll actually host `tmp/deploy/ipk` (e.g. an nginx serving that
  directory), since it gets baked into `/etc/opkg/*.conf` on the rootfs
  so devices can `opkg update`.
